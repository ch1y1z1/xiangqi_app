# 首版产品规格与页面布局

日期：2026-10-06。状态：首版核心功能已实现，共享 SwiftUI 工程可构建；运行与验证情况见 [开发说明](development.md)。

## 已确认的产品要求

- 个人使用，摆棋、保存、推演与皮卡鱼 AI 全部离线；无需登录或首次下载引擎模型。图片识别是选用的联网功能。
- 创建残局、自由摆放、选择先行方、保存、查看与继续推演。
- 双方手动为默认模式；支持 AI 推荐与 AI 接管对方。
- 推演保留多分支，回退改走不覆盖原线路。
- 棋盘始终默认红方在下，残局中可选黑方在下，不随轮次自动翻转。
- 绿灯表示我方可安全吃掉的对方棋子；红灯表示我方棋子可能被对方安全吃掉。安全指首次吃子合法，之后没有立即合法回吃。
- 必须有主要提示、动画与震动；快速开发优先，减少全面测试和额外兜底。
- 项目在公开 GitHub 仓库 `ch1y1z1/xiangqi_app` 中持续开发。
- 每次分支 push 成功构建后自动发布 GitHub Release，附带未签名 IPA、校验文件和对应调试符号；`main` 为正式版本，其他分支为预发布版本。
- 新增残局时可以从相册或文件导入棋盘图片。默认使用 DeepSeek 官方 `deepseek-v4-flash`，配置密钥及关闭、低、高、最高四档思考强度，默认高。另支持自定义 OpenAI 兼容 Chat Completions／Responses 接口，可填基础或标准完整地址、模型、可选密钥，支持 HTTP 局域网服务。自定义思考默认沿用服务配置，可手动指定标准强度。Apple 端侧识别后续再做。

## 页面布局

首版主要页面为残局库、编辑器、推演；设置与图片导入使用小面板，不增加复杂导航。

| 页面 | 顶部 | 主要内容 | 底部操作 |
| --- | --- | --- | --- |
| 残局库 | 应用名、“设置”、“新建” | 最近研究、缩略棋盘与残局名称；草稿标记 | 每张卡片提供可见的“…”菜单：修改名称、编辑棋子与名称、复制、删除 |
| 编辑器 | 返回、可编辑名称、“保存” | 图片识别入口；大棋盘，选中与目标位置提示；红黑棋子托盘与先行方 | 固定显示撤销、重做、删除棋子和“开始推演”，清空／初始盘在棋子托盘下 |
| 推演 | 残局名称、当前行棋方、菜单，支持改名和编辑棋子 | 大棋盘、上一手与落点；棋盘下方为当前线路及分支入口 | 上一手、下一手、AI 建议、托管；有建议时显示“采用此步” |

布局优先保证棋盘面积。编辑器托盘一次展示一方，通过红／黑切换；推演的 AI 结果区按需展开。棋盘翻转、提示开关、触感开关放在菜单中。

Mac 初期沿用接近手机宽度的内容区域，不增加独立桌面布局。点击与拖动共用棋盘命中逻辑；触感只在 iPhone 实现。

## 关键交互

**摆棋：** 点击托盘棋子类型，再点交叉点放置；拖动已有棋子调整。底部固定显示“删除棋子”：选中棋子后直接删除；未选中时进入连续删除模式，点击棋子即可删除，再点“完成删除”退出。删除可撤销，删除模式不允许拖动挪子。先提供空盘与初始局面两个起点。非法或未完成局面可保存为草稿，开始推演时显示具体校验原因。

**图片识别：** 设置中选择 DeepSeek 官方或自定义服务；自定义需填写接口类型、地址和视觉模型名称，支持 Bearer 密钥，也可使用无需鉴权的本地服务。两种服务的密钥分别保存到本机钥匙串，切换服务不复制密钥。配置点击“保存设置”才生效。编辑器选择“从图片识别残局”，从相册或文件选择单张完整棋盘图片。预览后点击“识别并导入”才上传到已保存的服务。通过同一 prompt 和 JSON 输出约束取得棋子颜色、类型、图片行列、图片朝向与可选先行方。检查坐标范围、重复位置和数量上限，再按图片朝向换算内部坐标。结果替换当前摆棋，默认红方在下；不明确的先行方暂用红先并提示检查。名称可从图片标题填入，手动命名优先。结果可修正后保存，推演前继续使用原有规则校验。取消识别不会导入迟到结果。图片不写入棋库，密钥不进入 JSON、日志或 Git。

**识别思考强度：** 与皮卡鱼搜索时间独立，随“保存设置”在本机保存。DeepSeek 保留关闭、低、高、最高四档和官方 thinking／reasoning_effort 参数，默认高。自定义服务默认不传思考强度及输出上限；指定时使用标准 reasoning_effort（Completions）或 reasoning.effort（Responses），关闭对应 none、最高对应 xhigh，并设置对应输出预算，需要服务与模型支持。更多思考会增加等待与额度消耗，但不能保证识别正确，结果仍先进入编辑器。

**识别期间切屏：** iOS 使用系统后台文件上传任务，正常切换 App 或锁屏不主动取消识别；明确点击“取消识别”才中止。任务和结果独立于页面保存，回到原识别页后继续显示进度或导入结果；App 被系统结束后重新打开，可从残局库的识别状态入口查看。恢复的结果需主动导入，不自动覆盖其他编辑中的残局。所选图片和请求仅暂存到排除备份的识别工作目录，导入或取消后删除，不进入棋库；完成后删除原始请求与响应。用户强制关闭 App 会取消系统传输，断网及服务超时也可能失败，不自动重新发起付费识别。

**编辑已保存残局：** 从残局卡片的“…”或推演页菜单选择“修改名称”／“编辑棋子与名称”。只改名或朝向会更新原残局并保留全部分支与当前节点；修改棋子或先行方会更新原残局、重置研究起点。如果已有推演，先保存完整“编辑前”副本以保留原线路。取消编辑不改动残局。

**研究：** 默认双方手动。只能按当前行棋方执行合法着法；上一手／下一手浏览当前线路；回退改走新增分支。重复走同一子着进入已有分支。

**AI 建议：** 点击后思考，显示推荐箭头和中文着法，按“采用此步”才落子。思考期间可停止；棋盘、分支或页面变化后旧结果失效。

**托管：** 选择双方手动、我执红／AI 执黑、我执黑／AI 执红。回退或切分支先暂停托管，由用户恢复。重启 App 后仍默认双方手动。

**红绿灯：** 默认以红方观察，即使轮到黑方，含义仍固定；选黑方在下后反过来。全盘提示按每条合法吃子关系计算，选中棋子时只突出该棋子的目标。将帅使用单独将军提示。

**反馈：** 选中轻抬起、移动约 200 ms、吃子淡出；iPhone 提供轻落子与稍重吃子震动，可关闭。先完整打磨一套视觉。

## 最小完成标准

1. 创建一个残局，保存并重开，手动推演，回退改走后两个分支均可继续。
2. 离线获得 AI 建议并采用，切换对方托管；回退时旧搜索结果不会落错棋；少量典型局面验证提示。
3. iOS 编译通过，随后在自己的 iPhone 上跑通流程，确认触摸、布局、震动与一次引擎内存／速度观察。

额外主题、标签收藏、批注、全树可视化、格式导入导出、复杂规则变体和全面测试体系后续按实际需要增加。
