# 首版产品规格与页面布局

日期：2026-10-05。状态：首版核心功能已实现，共享 SwiftUI 工程可构建；运行与验证情况见 [开发说明](development.md)。

## 已确认的产品要求

- 个人使用，核心功能全部离线；无需登录或首次下载模型。
- 创建残局、自由摆放、选择先行方、保存、查看与继续推演。
- 双方手动为默认模式；支持 AI 推荐与 AI 接管对方。
- 推演保留多分支，回退改走不覆盖原线路。
- 棋盘始终默认红方在下，残局中可选黑方在下，不随轮次自动翻转。
- 绿灯表示我方可安全吃掉的对方棋子；红灯表示我方棋子可能被对方安全吃掉。安全指首次吃子合法，之后没有立即合法回吃。
- 必须有主要提示、动画与震动；快速开发优先，减少全面测试和额外兜底。
- 项目在公开 GitHub 仓库 `ch1y1z1/xiangqi_app` 中持续开发。
- 每次分支 push 成功构建后自动发布 GitHub Release，附带未签名 IPA、校验文件和对应调试符号；`main` 为正式版本，其他分支为预发布版本。

## 页面布局

首版只有残局库、编辑器、推演三个主要页面；设置使用页面菜单或小面板，不增加复杂导航。

| 页面 | 顶部 | 主要内容 | 底部操作 |
| --- | --- | --- | --- |
| 残局库 | 应用名、“新建” | 最近研究、缩略棋盘与残局名称；草稿标记 | 每张卡片提供可见的“…”菜单：修改名称、编辑棋子与名称、复制、删除 |
| 编辑器 | 返回、可编辑名称、“保存” | 大棋盘，选中与目标位置提示；红黑棋子托盘与先行方 | 固定显示撤销、重做、删除棋子和“开始推演”，清空／初始盘在棋子托盘下 |
| 推演 | 残局名称、当前行棋方、菜单，支持改名和编辑棋子 | 大棋盘、上一手与落点；棋盘下方为当前线路及分支入口 | 上一手、下一手、AI 建议、托管；有建议时显示“采用此步” |

布局优先保证棋盘面积。编辑器托盘一次展示一方，通过红／黑切换；推演的 AI 结果区按需展开。棋盘翻转、提示开关、触感开关放在菜单中。

Mac 初期沿用接近手机宽度的内容区域，不增加独立桌面布局。点击与拖动共用棋盘命中逻辑；触感只在 iPhone 实现。

## 关键交互

**摆棋：** 点击托盘棋子类型，再点交叉点放置；拖动已有棋子调整。底部固定显示“删除棋子”：选中棋子后直接删除；未选中时进入连续删除模式，点击棋子即可删除，再点“完成删除”退出。删除可撤销，删除模式不允许拖动挪子。先提供空盘与初始局面两个起点。非法或未完成局面可保存为草稿，开始推演时显示具体校验原因。

**编辑已保存残局：** 从残局卡片的“…”或推演页菜单选择“修改名称”／“编辑棋子与名称”。只改名或朝向会更新原残局并保留全部分支与当前节点；修改棋子或先行方会更新原残局、重置研究起点。如果已有推演，先保存完整“编辑前”副本以保留原线路。取消编辑不改动残局。

**研究：** 默认双方手动。只能按当前行棋方执行合法着法；上一手／下一手浏览当前线路；回退改走新增分支。重复走同一子着进入已有分支。

**AI 建议：** 点击后思考，显示推荐箭头和中文着法，按“采用此步”才落子。思考期间可停止；棋盘、分支或页面变化后旧结果失效。

**托管：** 选择双方手动、我执红／AI 执黑、我执黑／AI 执红。回退或切分支先暂停托管，由用户恢复。重启 App 后仍默认双方手动。

**红绿灯：** 默认以红方观察，即使轮到黑方，含义仍固定；选黑方在下后反过来。全盘提示按每条合法吃子关系计算，选中棋子时只突出该棋子的目标。将帅使用单独将军提示。

**反馈：** 选中轻抬起、移动约 200 ms、吃子淡出；iPhone 提供轻落子与稍重吃子震动，可关闭。先完整打磨一套视觉。

## 最小完成标准

1. 创建一个残局，保存并重开，手动推演，回退改走后两个分支均可继续。
2. 离线获得 AI 建议并采用，切换对方托管；回退时旧搜索结果不会落错棋；少量典型局面验证提示。
3. iOS 编译通过，随后在自己的 iPhone 上跑通流程，确认触摸、布局、震动与一次引擎内存／速度观察。

额外主题、标签收藏、批注、全树可视化、格式导入导出、复杂规则变体和全面测试体系后续按实际需要增加。
