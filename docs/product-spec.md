# 首版产品规格与页面布局

日期：2026-10-07。状态：首版核心功能已实现，共享 SwiftUI 工程可构建；运行与验证情况见 [开发说明](development.md)。

## 已确认的产品要求

- 个人使用，摆棋、保存、推演与皮卡鱼 AI 全部离线；无需登录或首次下载引擎模型。图片识别是选用的联网功能。
- 创建残局、自由摆放、选择先行方、保存、查看与继续推演。
- 双方手动为默认模式；支持 AI 推荐与 AI 接管对方。
- 推演保留多分支，回退改走不覆盖原线路。
- 棋盘始终默认红方在下，残局中可选黑方在下，不随轮次自动翻转。
- 绿灯表示我方可安全吃掉的对方棋子；红灯表示我方棋子可能被对方安全吃掉。安全指首次吃子合法，之后没有立即合法回吃。
- 必须有主要提示、动画与震动；快速开发优先，减少全面测试和额外兜底。
- 项目在公开 GitHub 仓库 `ch1y1z1/xiangqi_app` 中持续开发。
- 每次分支 push 成功构建后自动发布 GitHub Release，附带未签名 IPA、校验文件和对应调试符号；`main` 为正式版本，其他分支为预发布版本。
- 新增残局时可以从相册或文件导入棋盘图片。默认使用 DeepSeek 官方 `deepseek-v4-flash`，配置密钥及关闭、低、高、最高四档思考强度，默认高。另支持自定义 OpenAI 兼容 Chat Completions／Responses 接口，可填基础或标准完整地址、模型、可选密钥，支持 HTTP 局域网服务。自定义思考默认沿用服务配置，可手动指定标准强度。Apple 端侧识别后续再做。

## 页面布局

首版主要页面为残局库、编辑器、推演；设置、原图与图片导入使用面板，不增加复杂导航。

| 页面 | 顶部 | 主要内容 | 底部操作 |
| --- | --- | --- | --- |
| 残局库 | 应用名、“设置”、“新建” | 紧凑残局列表、当前局面缩略图；最近有推演的残局标记“继续研究” | 每行提供 44 pt 的“…”菜单：修改名称、编辑棋子与名称、复制、删除 |
| 编辑器 | 取消、点按修改名称、图片／原图入口、“保存” | 固定棋盘；红黑双方各一排棋子与剩余数量；先行方、撤销、重做 | 选中棋盘棋子后出现“删除”；“开始推演”常驻底部；清空／初始盘／翻转在菜单 |
| 推演 | 紧凑返回与名称栏、当前行棋状态与评分、设置菜单 | 固定棋盘；当前线路横向浏览与分支比较；固定高度的 AI 建议／暂停状态区 | 起点、回退、前进／选择分支、AI 建议／停止／采用、当前操作模式 |
| 图片识别 | 返回、页面名称、服务设置 | 图片预览可放大；选图、识别中、失败、待校正四种状态 | 未配置时直接“配置识别服务”；识别中可停止；完成后明确“导入并校正” |
| 识别设置 | 取消、页面名称 | 服务、接口、地址、模型与密钥；思考强度和最终请求地址收进高级设置 | 保存设置；移除密钥也在保存时生效 |

编辑器与推演页在正常字号的 iPhone 竖屏内完成，按可用高度调整棋盘，整页不滚动；线路与参考变化局部浏览。推演建议出现时不改变棋盘大小，关闭红绿灯时图例及其空间一并移除。常用工具按钮至少 44 pt 点击区域；辅助文字使用较深色以提高对比度。图片识别页面用任务状态引导操作，不展示切屏、锁屏等实现能力宣传。

Mac 初期沿用接近手机宽度的内容区域，不增加独立桌面布局。点击与拖动共用棋盘命中逻辑；触感只在 iPhone 实现。

## 关键交互

**摆棋：** 红黑棋子同时显示，每排七种。点击托盘棋种，再点空交叉点放置；点按已有棋子切换选中，随后点空位或拖动移动。拖动到已有棋子的位置会拒绝操作，不覆盖或吃子。仅选中棋盘棋子时显示删除，删除后退出选择；无连续删除模式。删除、移动、放置、清空、恢复初始盘和图片替换均可撤销／重做。名称只在点按时输入；先行方和朝向独立。非法或未完成局面可保存为草稿，开始推演时在操作栏附近显示具体校验原因；文件保存失败使用独立提示。

**图片识别：** 设置中选择 DeepSeek 官方或自定义服务；自定义需填写接口类型、地址和视觉模型名称，支持 Bearer 密钥，也可使用无需鉴权的本地服务。两种服务的密钥分别保存到本机钥匙串，切换服务不复制密钥。配置与密钥移除点击“保存设置”才生效；取消不改动密钥。编辑器点击顶部图片入口，从相册或文件选择单张完整棋盘图片。预览后点击“识别棋盘”才上传到已保存的服务。通过同一 prompt 和 JSON 输出约束取得棋子颜色、类型、图片行列、图片朝向与可选先行方。检查坐标范围、重复位置和数量上限，再按图片朝向换算内部坐标。完成后点击“导入并校正”才替换当前摆棋，默认红方在下；不明确的先行方暂用红先并提示检查。名称可从图片标题填入，手动命名优先。结果可修正后保存，推演前继续使用原有规则校验。取消识别不会导入迟到结果。图片不写入棋库，密钥不进入 JSON、日志或 Git。

**识别思考强度：** 与皮卡鱼搜索时间独立，随“保存设置”在本机保存。DeepSeek 保留关闭、低、高、最高四档和官方 thinking／reasoning_effort 参数，默认高。自定义服务默认不传思考强度及输出上限；指定时使用标准 reasoning_effort（Completions）或 reasoning.effort（Responses），关闭对应 none、最高对应 xhigh，并设置对应输出预算，需要服务与模型支持。更多思考会增加等待与额度消耗，但不能保证识别正确，结果仍先进入编辑器。

**识别期间切屏：** iOS 使用系统后台文件上传任务，正常切换 App 或锁屏不主动取消识别；返回或关闭识别页保留任务；明确点击“停止”才中止。任务和结果独立于页面保存，回到识别页后显示进度或“导入并校正”；App 被系统结束后重新打开，可从残局库的识别状态入口查看。所有完成结果均需主动导入，不自动覆盖其他编辑中的残局。所选图片和请求仅暂存到排除备份的识别工作目录，导入或停止后删除工作目录，不进入棋库；导入时编辑器仅保留原图的内存副本供放大校正，保存或取消编辑后释放；完成后删除原始请求与响应。用户强制关闭 App 会取消系统传输，断网及服务超时也可能失败，不自动重新发起付费识别。

**编辑已保存残局：** 从残局卡片的“…”或推演页菜单选择“修改名称”／“编辑棋子与名称”。只改名或朝向会更新原残局并保留全部分支与当前节点；修改棋子或先行方会更新原残局、重置研究起点。如果已有推演，先保存完整“编辑前”副本以保留原线路。取消编辑不改动残局。

**研究：** 默认双方手动。只能按当前行棋方执行合法着法；起点／回退／前进浏览线路；前进沿本次研究已选的分支继续，尚未选择的多分支起点先弹出选择；回退改走新增分支。重复走同一子着进入已有分支。

**AI 建议：** 点击后思考，显示推荐箭头和中文着法，底部按“采用”才落子，参考变化另行查看。建议始终附带同次搜索的评分，不受两个常态展示开关影响。己方回合请求、取消或未能获得建议均保留对方托管状态；采用建议或自行另走一步后，未暂停的对方 AI 自动应手。已经暂停的托管不会因请求建议而自行恢复。思考期间可停止；棋盘、分支或页面变化后旧结果失效。仅实际托管走子的搜索失败时暂停托管并提示错误。

**局面与分支评分：** 两个独立开关分别控制常态显示当前局面评分和分支面板评分，默认开启，偏好保存在本机。当前评分紧凑显示在行棋状态旁；进入局面、落子、回退或切分支后刷新。分支面板只评估同一分叉点各个下一手后的局面，后续按双方最佳应对；不取不同长度的已保存线路末尾，也不分析整棵树。关闭当前评分仍可比较分支；两个开关都关闭仍可主动请求带评分的 AI 建议。计算和查看参考变化不落子、不新增研究节点。

**评分含义：** 普通评分统一红方视角，正分偏红、负分偏黑；朝向、行棋方和 AI 控制者不改变显示符号。引擎上／下界随视角换算，显示 ≤／≥；M 显示将杀或规则判胜的回合距离，未精确定界的胜线显示 ≈M；已终局显示红胜、黑胜或和棋。评分详情提供搜索深度和预算。当前局面与最佳 AI 着法的评分通常接近，不解释成“采用 AI 提升多少分”，也不换算成用户胜率。

**分支比较与计算：** 每个分支显示评分和深度，不重排已保存分支。只有本组所有候选均获得同档位的普通精确评分时，标出“本组较优”和其他分支相差的分数；红方行棋取较高分，黑方行棋取较低的红方分。将杀、终局、上下界和未完成结果不参与普通数值差比较。未完成显示计算中或待评估，不用 0.00 占位。复用现有快速／标准／深入的思考预算，每局面完成一次有限搜索；优先当前局面，再逐个分析当前展开的分支。用户请求 AI 时抢占后台分析，打开比较面板暂停正在托管的 AI。离开面板取消剩余分支任务；切局面、改设置或离开页面后旧回调失效。会话内按节点复用结果，修改初始局面或预算后清除评分，不改变残局 JSON 格式。提供重新分析／比较入口；失败不自动重复搜索。

**托管：** 选择双方手动、我执红／AI 执黑、我执黑／AI 执红。回退或切分支先暂停托管，由用户恢复。重启 App 后仍默认双方手动。

**红绿灯：** 默认以红方观察，即使轮到黑方，含义仍固定；选黑方在下后反过来。全盘提示按每条合法吃子关系计算，选中棋子时只突出该棋子的目标。将帅使用单独将军提示。

**反馈：** 选中轻抬起、移动约 200 ms、吃子淡出；iPhone 提供轻落子与稍重吃子震动，可关闭。先完整打磨一套视觉。

## 最小完成标准

1. 创建一个残局，保存并重开，手动推演，回退改走后两个分支均可继续。
2. 离线获得 AI 建议并采用，切换对方托管；回退时旧搜索结果不会落错棋；少量典型局面验证提示。
3. iOS 编译通过，随后在自己的 iPhone 上跑通流程，确认触摸、布局、震动与一次引擎内存／速度观察。

额外主题、标签收藏、批注、全树可视化、格式导入导出、复杂规则变体和全面测试体系后续按实际需要增加。
